# Внешняя API-интеграция

Использовать для подключения или изменения любого внешнего API.

## Процесс

1. Заполнить `../templates/api-integration-plan.md`.
2. Изучить актуальную официальную документацию и точную версию API.
3. Изучить текущий client, routes, storage, env и обработку ошибок.
4. Определить владельца данных и единственный источник истины.
5. Разделить read-only и write endpoints; write не выполнять без разрешения.
6. Хранить credentials и запросы с секретами только server-side.
7. Зафиксировать method, URL, headers, body, timeout и response schema.
8. Добавить ограниченный timeout и понятную безопасную ошибку.
9. Retry применять только к безопасным/idempotent операциям, с backoff и
   пределом попыток.
10. Логировать status, correlation ID и этап без токенов и персональных данных.
11. Проверить malformed response, 401/403, 429, 5xx, timeout и недоступность
   storage.
12. Проверить mapping по стабильным ID, а не по отображаемым названиям.
13. Выполнить минимальный безопасный запрос и сохранить фактический результат.
14. Применить `tablo-platform-consistency`, профильный integration skill и
   `tablo-regression-check`.
15. Отчитаться об endpoints, env, данных, ошибках, проверках и rollback.

## Стоп-условия

- Нет официальной схемы обязательных полей.
- Credentials смешаны между tenants или средами.
- Операция может изменить внешнюю систему без явного разрешения.

## Готово, когда

- Секреты не попадают в Git, UI, логи и client bundle.
- Ошибки наблюдаемы, но безопасны.
- Интеграция не создает второй источник истины.
