# Рефакторинг

Использовать только после явного согласования рефакторинга.

## Неподвижные границы

- Не менять пользовательское поведение.
- Не менять публичные и внутренние API-контракты без отдельного решения.
- Не менять дизайн, тексты и пользовательские сценарии.
- Не смешивать рефакторинг с новой функцией или багфиксом.

## Процесс

1. Описать цель, границы и проверяемое поведение до изменения.
2. Найти все импорты, call sites, тесты, routes и persistence.
3. Зафиксировать baseline: lint, TypeScript, build и затронутые сценарии.
4. Разделить работу на небольшие обратимые шаги.
5. Перемещать или упрощать код без изменения входов и выходов.
6. Удалять мертвый код только после `rg` по всем использованиям.
7. После каждого шага запускать узкую проверку затронутой области.
8. В конце применить полный `tablo-regression-check`.
9. Сравнить поведение и API с baseline.
10. Отчитаться о структуре до/после и доказательстве эквивалентности.

## Стоп-условия

- Для продолжения необходимо изменить поведение или данные.
- Обнаружен скрытый потребитель контракта.
- Нет способа проверить эквивалентность до и после.

## Готово, когда

- Все прежние сценарии работают без изменений.
- Мертвый код подтвержден и удален.
- Diff не содержит несвязанных продуктовых изменений.
